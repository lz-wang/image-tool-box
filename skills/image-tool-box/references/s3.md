# S3 兼容存储

仅在上传、下载、列举、查询或删除 S3 对象时读取。支持标准 S3 兼容接口，包括 AWS S3、MinIO、OSS、COS；实际能力以服务端支持情况为准。

## 连接配置

连接参数优先级为命令行参数 > `ITB_S3_*` 环境变量 > 默认值。凭据通过安全环境注入，不在示例、日志或命令历史中填入真实秘密。

| 环境变量 | 对应参数 | 用途 |
|----------|----------|------|
| `ITB_S3_ENDPOINT` | `-e, --endpoint` | 必填，服务端 URL |
| `ITB_S3_ACCESS_KEY_ID` | `-a, --access-key` | 必填，访问密钥 ID |
| `ITB_S3_SECRET_ACCESS_KEY` | `-s, --secret-key` | 必填，访问密钥 |
| `ITB_S3_SESSION_TOKEN` | `--session-token` | 临时凭据的会话令牌 |
| `ITB_S3_REGION` | `-r, --region` | 默认 `us-east-1` |
| `ITB_S3_BUCKET` | `-b, --bucket` | 必填，桶名称 |
| `ITB_S3_FORCE_PATH_STYLE` | `--force-path-style` | 强制路径式寻址 |

MinIO 通常使用 `--force-path-style`；回环地址及端口 `9000` 的端点自动启用。下面的示例假设连接参数和凭据已注入环境。

资源使用位置参数：`upload <src> [key]`、`download <key> [dst]`、`stat/delete <key>`、`list [prefix]`。不要使用已移除的 `--input`、`--output`、`--key`、`--prefix`。

## 常见用法

```bash
itb s3 upload photo.jpg images/photo.jpg --format json
itb s3 stat images/photo.jpg --format json
itb s3 download images/photo.jpg downloaded.jpg --verify --format json
itb s3 list images/ --all --format json
```

上传省略对象键时使用源文件名；下载省略目标时保存到当前目录，使用对象键最后一段作为文件名。默认上传覆盖同键对象，默认下载替换本地目标；按任务需要选择下述复用或不可覆盖策略。

只需判断对象是否存在或读取元数据时，优先用 `stat`：它只发一次 HEAD，不传输正文，也不退回到列举推断。

## 上传策略与发布

```bash
itb s3 upload photo.jpg images/photo.jpg --skip-unchanged --format json
itb s3 upload image.webp images/image.webp --skip-matching \
  --cache-control no-cache --metadata width=1920 --metadata height=1080 --format json
itb s3 upload original.png originals/original.png --if-exists verify --format json
itb s3 upload photo.jpg images/photo.jpg --verify --format json
```

| 策略 | 判断依据 | 行为 |
|------|----------|------|
| 默认 / `--if-exists replace` | 无 | 无条件写入并覆盖同键对象 |
| `--skip-existing` | 同键对象存在 | 跳过 |
| `--skip-unchanged` | `itb-sha256` 与本地内容一致 | 跳过，不以 ETag 判断 |
| `--skip-matching` | SHA-256、大小、Content-Type 及全部显式请求的响应头和元数据匹配 | 复用，`status=reused` |
| `--if-exists verify` | 真条件写 `If-None-Match="*"`；已有对象须匹配预期状态 | 缺失才写入；一致复用，不一致报 `E_TARGET_CONFLICT` |

三个 `--skip-*` 互斥。完整状态匹配只要求调用方显式指定的响应头与元数据子集，远端额外元数据不影响判断；未指定的响应头不要求为空。服务端不支持条件写时返回 `E_UNSUPPORTED_CAPABILITY`，不会降级为先 HEAD 再无条件 PUT。

上传通过稳定源快照保证 `itb-sha256` 对应实际上传字节；源在快照期间发生可观察变化时报 `E_SOURCE_CHANGED`。`--metadata key=value` 可重复，键转小写、非空且不含控制字符；`itb-sha256` 是保留键，不能自行指定。

使用 `--cache-control`、`--content-disposition`、`--content-encoding` 设置标准响应头。固定 URL 发布图片时可按缓存需求使用 `--cache-control no-cache`，以 `source-sha256`、`width`、`height` 等元数据记录来源；摘要应取实际值。

未指定 `--content-type` 时先按文件内容识别 MIME，再用扩展名兜底；改名成 `.jpg` 的 HTML 错误页不会被当作 JPEG。

上传 `--verify` 在 PUT 后做一次 HEAD，核对大小、Content-Type、响应头和元数据；它不重新下载正文，不能作为远端正文完整性证明。

## 下载校验与本地复用

```bash
itb s3 download images/photo.jpg downloaded.jpg --verify --format json
itb s3 download originals/source.png downloaded.png --verify-sha256 "$SOURCE_SHA256" \
  --if-exists verify --format json
itb s3 download images/photo.png downloaded.png --expect-size 123456 \
  --expect-content-type image/png --verify --format json
```

`SOURCE_SHA256`、预期大小和类型应来自任务中已知的可信依据，替换示例值后执行。

- `--verify` 单遍计算 SHA-256，与对象的 `itb-sha256` 元数据比较。
- `--verify-sha256 HASH` 与已知摘要比较，可与 `--verify` 同用。
- `--expect-size N` / `--expect-content-type MIME` 校验响应头及实际结果；`--expect-size 0` 是有效的零字节预期，与未设置不同。
- `--if-exists verify` 只在有摘要校验依据时复用本地文件；缺少依据立即失败，已有文件不一致时报 `E_TARGET_CONFLICT`。
- 复用也执行 `--verify` 和 `--expect-content-type` 要求的远端 HEAD 校验。仅已知摘要加可选大小的匹配副本可无网络复用。
- 下载先写临时文件，成功后替换；网络中断或校验失败均不留半成品。

## 列举与分页

```bash
itb s3 list images/ --format json
itb s3 list images/ --all --format json
itb s3 list images/ --all --page-size 500 --limit 5000 --format json
itb s3 list images/ --continuation-token "$NEXT_TOKEN" --all --format json
```

默认只取一页；`--page-size` 范围 `1–1000`，默认 `1000`，兼容别名为 `--max-keys`。`--all` 持续分页，`--limit N` 限制结果数量，`0` 不限。

`itb.s3.list.v2` 是结构化对象，包含 `bucket`、`prefix`、`complete`、`count`、`pages`、`next_continuation_token`、`objects`。空结果是 `complete=true` 与 `objects=[]`；截断时 `complete=false`，可用返回令牌恢复。

`complete=true` 仅表示从本次起始令牌开始的遍历正常完成。需要完整清单时从起点使用 `--all` 并检查 `complete`；不要把单页当完整清单。令牌缺失、重复或不前进时返回 `E_INCOMPLETE_LIST`。

## 删除

```bash
itb s3 delete images/photo.jpg
```

默认交互确认。仅在用户已明确要求无交互删除时加 `-f`；先核对桶和对象键。

## 网络控制与机器可读结果

`--max-attempts` 默认 `3`；`--connect-timeout` / `--response-header-timeout` 默认各 `30s`，默认不限制正文传输时间。`--operation-timeout` 默认 `0`，表示不限制整个操作；设置总超时时要考虑大文件传输。

`upload` / `download` / `stat` 支持 `--format table|json`，`list` 还支持 `plain`。成功 JSON 分别为 `itb.s3.upload.v2`、`itb.s3.download.v2`、`itb.s3.stat.v1`、`itb.s3.list.v2`。上传 `status` 为 `uploaded/skipped/reused`，下载为 `downloaded/reused` 并包含 `content_type`；上传旧字段 `skipped/reason` 保留。

JSON 失败契约为 `itb.error.v1`，包含 `schema_version`、`operation`、`error{code,message,retryable,http_status,provider_code}`。按稳定错误码处理，如 `E_INVALID_ARGUMENT`、`E_OBJECT_NOT_FOUND`、`E_ACCESS_DENIED`、`E_CHECKSUM_MISMATCH`、`E_INCOMPLETE_LIST`、`E_TIMEOUT`、`E_NETWORK`、`E_THROTTLED`；`retryable` 表示相同操作重试可能成功。输出不会包含凭据或签名 URL。
